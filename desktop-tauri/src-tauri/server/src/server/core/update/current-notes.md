1. 新增：OpenCode 免费档的四种拒绝原因分别识别 —— 客户端形态门禁 / 地区封锁 / 该出口额度耗尽 / 模型不在免费档，各给一条能照着做的提示。此前四条被压成一句「上游凭证被拒绝（检查 apiKey）」，而它们全都与 Key 无关，照着改改到天亮也没用
2. 新增：OpenCode 通道冷却 —— 形态门禁 10 分钟内不再打这家（改请求头能修，换出口是白花往返）；地区封锁 10 分钟、额度耗尽 60 秒，都只钉住出问题的那一个出口。额度冷却以 429 快速失败，好让「换个出口重发」这条既有补救继续生效，不会被自己的冷却挡住；「模型不在免费档」则完全不冷却 —— 一个写错的模型名不该把这家所有模型一起锁十分钟
3. 新增：形态门禁被拒时自动降级到另一条通道重试一次（`/inference/v1` ↔ `/zen/v1`）。两条通道的指纹规格不同，被否的是这一套指纹，不是这个账号，换过去常常就通了
4. 新增：`/zen/v1` 通道的完整支持 —— 它要的是自己那一套出站头（UA 形如 `opencode/1.18.31 (<os> <arch>; bun/1.3.14)`、`x-opencode-request` 必发、`prj_` 形 project）与请求体形态（只补一个 `read` 工具，与 inference 面的 `bash` + `read` 正好相反）。早前「`/zen/v1` 已废弃、打它一律 403」的结论，是用 inference 的指纹去打 zen 造成的误判，本次一并修正
5. 新增：OpenCode 免费档的出口并发闸 —— 同一个出口最多 4 个上游请求在飞（按 IP 计，不按 provider 计：两个家走同一个代理就是在共用同一份预算），等 30 秒仍无空位回 503 快速失败。依据是社区实测：同一出口连发 10 个大请求会触发 IP 级标记，那种标记连 600 秒冷却都不一定救得回来。许可只覆盖到「响应头到手」，不持有整条长连接
6. 修复：OpenCode 免费档的 403 / 429 不再一律报「凭证被拒绝」—— 四条成因的处置方式完全不同（改指纹 / 换出口 / 等或换出口 / 换模型），提示里逐条写清「该改什么」与「改了也没用的是什么」
7. 优化：OpenCode 伪装请求自动补 `stream_options.include_usage`（仅在客户端没写这一项时）—— 不设它时上游的流式响应通常不带 usage，报表里的 Token 消耗会恒为 0
8. 优化：OpenCode 的冷却与并发闸按同一个出口键（`host:port`）记账，直连也算一个出口；成功一次即解除该通道全部冷却，上游恢复后不再按旧标记惩罚
9. 新增：单文件分发形态 —— 新增 `embed-ui` 编译开关，把整个面板内嵌进可执行文件，一个 exe 拷到任何 Windows 上双击就能跑（默认关闭，不开时行为与之前逐字相同）
10. 优化：静态资源托管改为「磁盘优先、内嵌兜底」—— 旁边有 `ui/` 时仍走磁盘（面板自更新照旧生效），没有才用内嵌的那一份；启动日志会说明这次用的是哪一份
11. 更新：「关于作者」改为「本工具引用 aimod-cc 的开源项目，由 funwukong 修改」；署名固定指向上游作者，不随更新仓库地址（`WORKBUDDY_UPDATE_REPO`）漂移
12. 版本：3.0.8 → 3.88.0
